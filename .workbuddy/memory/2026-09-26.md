## ABI 专题：读 Ch06 §6.2/6.3.2/6.4/6.5 + Ch07 §7.9 + Ch11 §11.2 + Ch13 → `doc/go_abi.md`

产出：`doc/go_abi.md`（约 640 行），11 节 + 一页速记。已在 `go_book_mapping.md` 头部与 Ch06 末尾加交叉引用。

**结构**：§1 ABI 定义（书 §6.5 的四项责任：命名/资源分配/可寻址性/保护）→ §2 一次调用四段（precall/postreturn/prologue/epilogue + "往 callee 挪"原则）→ §3 AR 七字段与栈/堆/静态分配 + access link/display → §4 传参四语义 + Go 参数分类算法 + spill space → §5 寄存器保存（书折中 vs Go 全 caller-save）→ §6 ABI0 vs ABIInternal → §7 Ch11 §11.2 后端正支柱与 ABI 的耦合 → §8 Ch13 + Go 线性扫描 → §9 端到端时序 → §10 误区表 → §11 验证命令。

**核对过的 Go 事实（可复用）**：

- `abi-internal.md`：amd64 整数参数寄存器 = `RAX,RBX,RCX,RDI,RSI,R8,R9,R10,R11`（9 个），浮点 `X0–X14`；`R12/R13` 永久 scratch；`R14`=goroutine、`RDX`=闭包上下文、`X15`=零值寄存器、`RBP`=帧指针。
- **Go 没有 callee-save 寄存器**（原文 "There are no callee-save registers"），理由：简化 GC 与 regalloc。注意 RBX 在平台 ABI 里是 callee-save，Go 拿来当参数寄存器。
- arm64：`R0–R15` 整数参数、`F0–F15` 浮点、`R30` link register、`R29` 帧指针、`R28` goroutine、`R26` 闭包上下文、`ZR` 零值。
- **ABI0 = ABIInternal 在 NI=NFP=0 时的退化**（`abi-internal.md` Rationale 明说），所以两套约定可共用一份生成代码。
- 参数分类算法：递归拆到 base type；string/interface 拆 2 个、slice 拆 3 个；**长度 >1 的数组一律失败→整个参数走栈**（0/1 元素例外）；参数失败时寄存器下标要回滚。
- **argument spill space 由 caller 预留**，因为要支持 `runtime.morestack` 的静态 spill 路径；中位数浪费 16 字节/调用。
- 闭包 = `&struct{F uintptr; X...}`（`walk/closure.go:170` 注释；`typecheck/func.go:93` 同）。
- `internal/abi/iface.go`：`ITab{Inter,Type,Hash,Fun[1]uintptr}`；空接口 = `EmptyInterface{Type,Data}`，非空接口 = `NonEmptyInterface{ITab,Data}`。
- `ssa/regalloc.go` 头注释（:5–25, :27–82）：线性扫描 + 把整个函数当一个长基本块 + 贪心 + **spill 下次使用最远**；要求无 critical edge；spill 插在"所有 restore 的共同支配者"处；phi 分 register phi / stack phi 两类。

**踩过的坑（重要）**：

- SSA 调试开关只接受 `-d=ssa/<phase>/<flag>`，phase 名来自 `ssa/compile.go` 的 `passes` 数组、**空格换下划线**（`"expand calls"` → `expand_calls`），flag 只有 `on/off/debug/mem/time/test/stats/dump/seed`。
- **`debug=N` 只对真的调用 `f.Log` 的 pass 有输出**——`regalloc.go` 里没有 `f.Log`，所以 `-d=ssa/regalloc/debug=1` 是空跑。要观察 regalloc 用 `GOSSAFUNC="Foo:lower,regalloc" go build`（生成 ssa.html）或 `-d=ssa/<phase>/dump=<func>`。权威说明在 `ssa/README.md:190` 起。
- `expand_calls` 是 pass 名（`compile.go:477`），不是单独阶段。

## 重写规则（rules）专题：读 `_gen/*.rules` + `_gen/rulegen.go` + `rewrite.go`

**规模（go1.27.1 实测）**：21 个 `.rules` / 20643 行 → 展开后 **14364 条**规则（按生成物里的 `// match:` 计数）→ 约 20 万行生成 Go（`rewritegeneric.go` 39873、`rewriteAMD64.go` 110076；含 `opGen.go` 116916 则生成物共约 32 万行）。单架构最多：AMD64 4961 条、ARM64 1417 条。

**规则 → 生成物 → pass 的映射**（`_gen/*.rules` 是唯一真源）：

| 规则文件 | 生成物 | 驱动 pass |
|---|---|---|
| `generic.rules` | `rewritegeneric.go` | `opt`（`opt.go:9`，passes 里跑 3 次） |
| `<ARCH>.rules` + `simd<ARCH>.rules` | `rewrite<ARCH>.go` | `lower`（`f.Config.lowerValue`，`config.go:183` 起） |
| `<ARCH>latelower.rules` | `rewrite<ARCH>latelower.go` | `late lower`（`config.go:185`） |
| `<ARCH>splitload.rules` | `rewrite<ARCH>splitload.go` | **异常**：不是 pass，由 `flagalloc.go:136`、`addressingmodes.go:97` 对单个值按需调用 `f.Config.splitLoad(v)` |
| `dec.rules` / `dec64.rules` | `rewritedec*.go` | `decompose builtin`（`decompose.go:30,32`） |
| `divmod.rules` / `divisible.rules` | `rewritedivmod/divisible.go` | `divmod` / `divisible`（`opt.go:13,17`） |

**语法要点**（`rulegen.go` 顶部注释 + `generic.rules` 头注释）：`(match) && 条件 => @block (result)`；匹配侧 `(op <类型> [AuxInt] {Aux} 子节点…)`；变量首次出现即绑定、后续必须指针相等；**文件顺序 = 优先级，第一条命中胜出**；`|` 组展开（一行变多条，各 `|` 组个数必须一致）；`...` 省略号规则生成 `v.Op = X; return true`；`___` 表示忽略额外参数；RHS `{ Go代码 }` 是逃生舱口（如 `AMD64.rules:864` 的强度削减）。

**引擎**：`rewrite.go` 的 `applyRewrite(f, rb, rv, deadcode)` —— 顺序扫块/值 → 按 `v.Op` 分派 → 命中就 `reset`/`copyOf` 原地改写 → 整个函数重复到不动点；迭代次数超过 `f.NumBlocks()`（下限 20）时启动环检测，检测到环则 `Fatal("rewrite cycle detected")`。`clobber(vv...)`（`rewrite.go:1045`）不返回值、只把节点置 `OpInvalid` 并减引用计数，供 `x.Uses == 1` 类规则使用。

**规则调试利器**（写在 `rewrite.go:1072-1095`）：条件里塞 `noteRule("msg")` 命中即打印；`countRule(v, key)` 计数并在编译结束输出 `Func.ruleMatches`。

**书 ↔ 代码的差异**：书 §11.4.2 的「寻找铺盖」是 BURG 式动态规划求最优 tiling，Go 实际是**按序贪心重写 + 迭代到不动点**，不保证最优；`rulegen.go` 对应 §11.4.3 的工具层（注释自陈思路来自 Swift/Java 编译器的 WRL-2000-2 报告）。

**生成物约束**：`generate.go:9` 的 `//go:generate go run -C=_gen .`；`ssa/generate_test.go` 的 `TestGeneratedFilesUpToDate` 会在生成物过期时报错；`_gen/cover.bash` 用临时 `main_test.go` 量 rulegen 自身覆盖率。改规则必须连生成物一起提交。
