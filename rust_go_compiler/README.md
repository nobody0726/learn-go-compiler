# rust_go_compiler — bootstrap coverage tooling

This directory is the eventual home of the Rust rewrite of Go 1.27.1's
`cmd/compile`. Nothing of the compiler exists yet. What exists **today** is
the bootstrap tooling that enforces the "no-omission" model defined in
[`doc/rust_go_compiler_architecture.md`](../../doc/rust_go_compiler_architecture.md)
and [`doc/rust_go_compiler_rewrite_plan.md`](../../doc/rust_go_compiler_rewrite_plan.md):
the **three ground-truth sets** (A/B/C) and the **four-gates validator**.

## Why this exists before the compiler

"Zero omission" cannot be claimed from a single ground truth. The Go spec
under-describes what the compiler implements (PGO, write barriers,
ABIInternal, PCLN, escape diagnostics) and over-describes runtime behavior
(goroutine/map/select randomization). The only way to surface omissions is
three **independent, machine-regenerable** truth sets, diffed pairwise, with
a validator that fails loudly when a feature touches fewer than all three.

## Layout

```
tools/
  models.py                  shared dataclasses + stdlib TOML I/O
  extract_spec_atoms.py      set A: parse doc/go_spec.html h2/h3
  extract_impl_atoms.py      set B: scan tree (pragma/flag/rules-by-pass/obj)
  extract_test_atoms.py      set C: enumerate test tree (L1/L3/L5)
  validate_features.py       four-gates validator (CLI + library)
  triangle_diff.py           A x B x C x features.toml -> the three red zones
tests/
  test_validate_features.py  RED-first unittest (stdlib, 12 cases)
  test_triangle_diff.py      RED-first unittest (stdlib, 22 cases)
coverage/
  spec_atoms.toml            generated (A)
  impl_atoms.toml            generated (B)
  official-tests.toml        generated (C)
  features.toml              hand-edited attribution; policed by validator
  triangle-diff.txt          generated red-zone report (--out)
```

## Run

```sh
cd rust_go_compiler
PY=python3   # requires Python >= 3.11 (stdlib tomllib)

# 1. Regenerate the three ground-truth sets from go_source_code/
PYTHONPATH=tools $PY tools/extract_spec_atoms.py
PYTHONPATH=tools $PY tools/extract_impl_atoms.py
PYTHONPATH=tools $PY tools/extract_test_atoms.py

# 2. Validate the hand-attributed features.toml against the four gates
PYTHONPATH=tools $PY tools/validate_features.py coverage/features.toml

# 3. Triangle diff: which ground-truth atoms has nobody claimed?
PYTHONPATH=tools $PY tools/triangle_diff.py                  # summary
PYTHONPATH=tools $PY tools/triangle_diff.py --full           # no truncation
PYTHONPATH=tools $PY tools/triangle_diff.py --json           # machine-readable
PYTHONPATH=tools $PY tools/triangle_diff.py --out coverage/triangle-diff.txt

# 4. Run the RED-first unit tests
PYTHONPATH=tools $PY -m unittest discover -s tests -v
```

Only the Python standard library is used (`tomllib`, `re`, `pathlib`,
`unittest`) — no PyPI dependency, so it runs in the sandbox as-is.

## The four gates (static portion enforced here)

| Gate | What | Enforced by |
|---|---|---|
| 1 mechanical | A/B/C "source side" regenerated by scripts, humans only attribute | re-running the extractors + diffing output |
| 2 triangulation | each feature has >=1 spec_atom AND >=1 impl_atom AND >=1 test_atom | `E_NO_SPEC` / `E_NO_IMPL` / `E_NO_TEST` |
| 2b ref integrity | every cited `atom_id` really exists in A/B/C | `triangle_diff.py` section `[0]`, exit 1 |
| 3 mutation | a `verified` feature cites a `mutation_case_id` | `E_NO_MUTATION` |
| 4 negative | each feature has >=1 `negative_test_id` | `E_NO_NEG` |

Gates 1 and 3's runtime half (does the harness actually catch an injected
bug?) need a runnable compiler; their static proxies are in place now so the
contract is enforced from day one.

## Current numbers (go1.27.1, machine-generated)

| Set | Count | Breakdown |
|---|---|---|
| A spec_atoms | 125 | 19 h2 + 106 h3 clauses |
| B impl_atoms | 183 | 19 pragma + 66 flag + 27 rules(pass-grouped) + 71 obj |
| C test_atoms | 2738 | 2728 L1 (+87 carry `also_in=["L2"]`) + 1 L3 stub + 9 L5 |

### Why C is 2738 and not 2825

The first version emitted a second atom (`L2:codegen:<file>`) for every file in
`test/codegen`. But `dirs[]` in `testdir_test.go` already contains `"codegen"`,
so all 87 of those files were counted twice. One physical file must be one atom
that needs claiming once, so the L2 view is now an attribute
(`also_in = ["L2"]` + `asmcheck_assertions`) on the L1 atom. The triangle diff
is what surfaced this -- a duplicated atom inflates every denominator silently.

## Triangle diff (`triangle_diff.py`)

`validate_features.py` reads `features.toml` alone: it can prove an entry is
malformed, never that an atom is *unclaimed*. This is the other half, and it
prints the three red zones the no-omission model is built around:

| Zone | Meaning | Where omissions hide |
|---|---|---|
| A-only | spec clause with no `feature_id` | spec dead corner -- all tests green, semantics still missing |
| B-only | impl atom with no `feature_id` | impl-only contract (PGO, write barriers, ABIInternal) -- spec cannot help |
| C-only | official test with no `feature_id` | runtime behavior, only observable by running |

Plus section `[0]`: **dangling references** -- a feature citing an `atom_id`
that does not exist in the generated sets. That is a data error, not a TODO,
because such a citation claims nothing while looking like it claims something.
Exit code is `1` when any are found, `0` otherwise (red zones are expected
work-in-progress and do not fail the run).

Current result on go1.27.1 with the 2-feature seed:

```
baseline   A=125   B=183   C=2738   features=2
claimed    A 2/125 (1.6%)   B 3/183 (1.6%)   C 3/2738 (0.1%)
[0] dangling 0        VERDICT: OK
red zones total 3038
```

That 3038 is the honest size of the unattributed surface. It is not a bug
list -- it is the work remaining, now enumerated instead of guessed.

These are **ground-truth sizes**, not pass counts. Growing the attribution is
human work guided by the `doc/go_book_mapping.md` navigation; `triangle_diff.py`
tells you exactly which atoms are still unclaimed and in which order the spec
presents them.

### Known signal-to-noise issue in the A zone

Two spec h2 sections (`Introduction`, `Notation`) are expository -- they
describe how the spec is written, not behavior a compiler implements. They
will therefore sit in A-only forever. The candidate list for a `claimable =
false` marker (to be confirmed, not assumed) is: `Introduction`, `Notation`,
and possibly `Appendix` and `System considerations`. A-only is 123 clauses, so
this is ~2% noise today -- worth fixing before the zone is used as a work
queue, not before.

## Why Python for the bootstrap

`cargo`/`rustc` are not yet installed in this environment, and the
architecture doc deliberately places `tools/` outside the Rust crate graph
(they are build tooling, like rustc's `x.py`). TOML output is
language-agnostic, so the atom sets produced here will feed the Rust
compiler unchanged once it exists. When the Rust workspace is bootstrapped,
these generators can be re-implemented in Rust behind the same file
contracts with no change to `coverage/*.toml`.
